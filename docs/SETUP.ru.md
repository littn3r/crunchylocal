# Настройка

[← README](../README.ru.md) · [English](SETUP.md) · **Русский**

## Создание настроек

Контейнер настройки создаёт в папке проекта два приватных файла:

| Файл | Назначение |
| --- | --- |
| `.env` | Адрес плеера и автоматически созданный ключ шифрования сессий |
| `oauth_apps.json` | Необязательные ключи приложений Shikimori и MAL |

Существующие файлы сохраняются. Если адрес плеера изменился, исправьте `.env`. После изменения настроек пересоздайте контейнер приложения.

На Linux контейнер настройки по умолчанию использует UID/GID 1000. Если у вашего пользователя другие значения:

```sh
LOCAL_UID=$(id -u) LOCAL_GID=$(id -g) docker compose -f compose.setup.yaml run --rm setup http://127.0.0.1:8765
```

Для существующей установки сохраните её `.env` и `oauth_apps.json`; новый ключ создавать не нужно.

## OAuth

Интеграции списков необязательны. Зарегистрируйте нужные сервисы:

| Сервис | Регистрация приложения | Ключ в `oauth_apps.json` | Путь возврата |
| --- | --- | --- | --- |
| Shikimori.io | [OAuth-приложения](https://shikimori.io/oauth/applications) | `one` | `/shiki/callback` |
| Shikimori RIP | [OAuth-приложения](https://shikimori.rip/oauth/applications) | `rip` | `/shiki/callback` |
| MyAnimeList | [Настройка API](https://myanimelist.net/apiconfig) | `mal` | `/mal/callback` |

Redirect URL — адрес плеера плюс путь из таблицы, например `http://127.0.0.1:8765/mal/callback`. Для Shikimori включите разрешение `user_rates`, для MAL выберите тип Web.

Заполните `client_id` и `client_secret` в приватном `oauth_apps.json`, созданном через `tools/init_config.py`, затем пересоздайте контейнер приложения. Внутренний ключ `one` обозначает shikimori.io. Поддерживаемые адреса RIP: `shikimori.rip`, `shikirip.top`, `shikimori.net`.

Подключите сервис через меню аккаунтов. В плеере выберите запись сезона и сервисы для синхронизации. Автоматическое обновление прогресса сохраняет личные оценки и не уменьшает число просмотренных серий; ручное сохранение отправляет значения из формы. Списки автоматически не объединяются.

## Удалённый доступ по HTTPS

Приложение обслуживает HTTP на `127.0.0.1:8765`. HTTPS обеспечивает прокси на хосте: Caddy, Nginx, уже настроенный прокси или Tailscale Serve. Это работает с Docker-профилем. Используйте отдельный домен с плеером в корне, например `https://player.example.com`; размещение по пути `/player/` не поддерживается.

### Свой домен и HTTPS

**1. Подготовьте домен.** Направьте DNS-запись на сервер. Для публикации нужен входящий доступ; дома могут потребоваться проброс портов и публичный IP. Для доступа только внутри локальной сети подойдут внутренний DNS и сертификат, которому доверяют ваши устройства. Tailscale не требуется.

**2. Укажите адрес сайта.** Для новой установки:

```sh
docker compose -f compose.setup.yaml run --rm setup https://player.example.com
```

Для существующей установки измените строку в `.env`: команда настройки сохраняет существующие файлы.

```dotenv
CRUNCHY_LOCAL_PUBLIC_ORIGIN=https://player.example.com
```

Сохраните ключ шифрования сессий. Укажите точный адрес из браузера, включая нестандартный порт, если он используется, без пути и завершающего слеша.

**3. Настройте прокси.** Примеры ниже рассчитаны на прокси, установленный непосредственно на том же хосте, где работает Docker. Выберите один вариант.

#### Caddy: автоматический сертификат

[Установите Caddy](https://caddyserver.com/docs/install) и добавьте в Caddyfile:

```caddyfile
player.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

Перезагрузите конфигурацию Caddy через службу вашей системы. Для автоматического публичного сертификата DNS должен вести на сервер, а порты проверки ACME должны быть доступны извне; стандартная настройка использует 80 и 443. Caddy самостоятельно продлевает сертификат. Подробнее — [Automatic HTTPS](https://caddyserver.com/docs/automatic-https).

Для собственного сертификата добавьте строку `tls` внутрь того же блока:

```caddyfile
    tls /path/to/fullchain.pem /path/to/privkey.pem
```

Сертификат должен соответствовать домену, включать нужную цепочку и быть доверенным на всех устройствах для просмотра. Его продление организуйте самостоятельно. Для сертификата частного центра сертификации установите его корневой сертификат на устройства; обход предупреждения браузера не обеспечивает надёжную работу DRM.

#### Nginx: собственный сертификат

В установленном Nginx добавьте эти блоки в HTTP-конфигурацию, заменив домен и пути сертификата:

```nginx
server {
    listen 80;
    server_name player.example.com;
    return 301 https://player.example.com$request_uri;
}

server {
    listen 443 ssl;
    server_name player.example.com;
    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    client_max_body_size 4m;

    location / {
        proxy_pass http://127.0.0.1:8765;
        proxy_http_version 1.1;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
        proxy_buffering off;
        proxy_buffer_size 32k;
        proxy_buffers 8 32k;
        proxy_cache off;
    }
}
```

На Linux проверьте конфигурацию командой `sudo nginx -t`, затем примените её через `sudo systemctl reload nginx`. Получите действующий сертификат и настройте его продление отдельно: этот пример Nginx не выпускает сертификат. Официальные инструкции: [HTTPS](https://nginx.org/en/docs/http/configuring_https_servers.html) и [проксирование](https://nginx.org/en/docs/http/ngx_http_proxy_module.html).

Для другого прокси сохраняйте `Host`, передавайте `X-Forwarded-Proto: https`, все пути и параметры запросов, отключите кеширование ответов авторизованных пользователей. Приложение должно оставаться доступным только через прокси или localhost. Если прокси работает в отдельном контейнере, `127.0.0.1` означает сам контейнер: настройте общую сеть или подключение к хосту; адрес из примера без изменений не подойдёт.

**4. Запустите или пересоздайте приложение.**

```sh
docker compose up -d --build --force-recreate app
```

**5. Обновите вход и проверьте работу.**

- Зарегистрируйте `https://player.example.com/shiki/callback` и/или `https://player.example.com/mal/callback` в соответствующих OAuth-приложениях.
- Для расширения Chromium или Tampermonkey [настройте адрес домена](#вход-в-crunchyroll), пересоберите приложение и переустановите обновлённое расширение/скрипт. В распространяемой версии по умолчанию разрешён localhost.
- Откройте HTTPS-адрес без предупреждений о сертификате, войдите и проверьте просмотр на нужном устройстве.

Отдельных аккаунтов для ограничения доступа к самому сайту нет. Если домен доступен из интернета, ограничьте доступ на прокси, например авторизацией или списком разрешённых IP. Храните `.env`, секреты OAuth и закрытые ключи сертификатов вне публичных файлов.

## HTTPS и Tailscale

Установите Tailscale на сервер и устройства, с которых будете смотреть, и подключите их к своей сети. При запущенном плеере:

```sh
sudo tailscale serve --bg http://127.0.0.1:8765
```

Используйте HTTPS-адрес, который покажет Tailscale. Укажите его в `CRUNCHY_LOCAL_PUBLIC_ORIGIN` в `.env`, обновите Redirect URL приложений OAuth и пересоздайте контейнер приложения.

Docker-профиль слушает только localhost. Tailscale Serve открывает доступ внутри вашей сети Tailscale; сайт не публикуется в открытом интернете. Обычный HTTP по локальному IP не подходит для DRM-воспроизведения.

## Вход в Crunchyroll

Введите почту и пароль в плеере. Сервер передаст их Crunchyroll через временный браузер. Если потребуется дополнительная проверка, откройте предложенное плеером окно подтверждения.

На компьютере можно входить через официальный сайт Crunchyroll с расширением для Chromium либо скриптом Tampermonkey (Firefox и совместимые браузеры Chromium). Импорт `cookies.txt` тоже доступен.

Для Tampermonkey установите менеджер с [официального сайта](https://www.tampermonkey.net/), затем нажмите **«Установить скрипт Tampermonkey»** в окне входа плеера. Для доступа к HttpOnly используйте Tampermonkey Beta, как указано в его документации. В общих **Settings** менеджера выберите **Config mode → Advanced**, затем **Security → Allow scripts to access cookies → All**. Обновите плеер и нажмите кнопку входа. Скрипт читает только `etp_rt`, передаёт её настроенному плееру и не сохраняет сеансы в хранилище скриптов. Отдельная подпись Mozilla ему не нужна.

Настройка расширения и скрипта для своего сервера:

```sh
docker compose -f compose.setup.yaml run --rm --entrypoint python setup tools/configure_extension.py https://player.example.com
```

Установите распакованное расширение через режим разработчика браузера. После изменения его конфигурации пересоберите контейнер приложения. Обычный Chrome на телефоне не поддерживает расширение; используйте форму входа плеера.

## Обслуживание

Для приложения:

```sh
docker compose logs --tail=100 app
docker compose up -d --build --force-recreate app
docker compose down
```

Каталог обновляется при запуске и раз в сутки. При ошибке сохраняется рабочая версия. В Docker кеш находится в томе `catalog-data`; `down -v` удаляет его. Период задаётся в `.env` через `CRUNCHY_LOCAL_CATALOG_INTERVAL` (секунды, 3600–604800; по умолчанию 86400).

| Проблема | Что проверить |
| --- | --- |
| ShakaError 6020 | Используйте localhost или HTTPS: Chrome/Chromium с Widevine либо Safari на macOS с FairPlay. |
| Crunchyroll HTTP 420 | Остановите просмотр в других вкладках. После оборванного сеанса подождите несколько минут, пока Crunchyroll освободит его, и повторите попытку. |
| Ошибка OAuth | Redirect URL и `CRUNCHY_LOCAL_PUBLIC_ORIGIN` должны точно совпадать. |
| Вход требует подтверждения | Используйте окно проверки; защита сервиса может отклонять серверный браузер. |
| Нет информации об аниме | Возможно, нет сопоставления с MAL/Shikimori или данных источника; просмотр остаётся доступным. |

## Приватные файлы

Не публикуйте `.env`, `oauth_apps.json`, `.local/`, профили браузера и логи. Смена ключа шифрования делает существующие cookies аккаунтов недействительными. Владелец сервера имеет доступ к данным во время обработки запросов; хранение сессии в браузере не устраняет необходимость доверять серверу.
